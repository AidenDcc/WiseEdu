## 附：导入 Word / PDF 的技术结论（避免返工）

| 格式 | 结论 | 推荐方案 |
|---|---|---|
| `.docx` | **可解析、可编辑**。OOXML 是结构化标记 | 预览用 `docx-preview`（高保真、只读）；编辑用 `mammoth`（docx → 语义 HTML → 喂 DocCanvas）。要最高保真且能接受独立场景，可用 LibreOffice headless 服务端转换 |
| `.pdf` | **只能只读预览，不能无损编辑**（PDF 内无"段落"语义，信息已丢失） | 预览用 `pdf.js`；要可编辑只能 OCR + 版面分析 / AI 重建（本质是重生成，公式表格会走样） |

**两个必踩的坑**（写进验收）：
1. mammoth 产出的 HTML 会含 TipTap schema 之外的标签（`<h5>` / `<pre>` / `<div>`）——项目关掉了 `codeBlock`、`horizontalRule`，标题只到 4 级 —— 直接 `setContent` 会被**静默丢弃**（表现为"导入成功但少了半页"）。必须加一层「HTML → TipTap schema」的清洗降级。
2. 图片：mammoth 默认输出内联 base64，而项目规定 `allowBase64: false`（正文只存 URL）。图片须抽出上传媒体库再替换成 URL。

## 附：插件化架构建议（"二开插件"怎么落地）

每个功能插件统一定义为三件套，注册进一张表：

```
{
  id,            // 唯一标识
  group,         // 功能区归属：字体 / 段落 / 插入 / 表格 / 页面 ...
  icon, label,   // 工具栏按钮
  command,       // 无弹层的直接执行（TipTap chain）
  panel,         // 有弹层的组件（如段落对话框、表格面板）
  isActive,      // 当前选区是否生效（按钮高亮）
  isEnabled,     // 当前上下文是否可用（如不在表格里就禁用表格操作）
  shortcut,      // 快捷键绑定
}
```

好处：工具栏由注册表渲染 → 增删功能只改数据；功能与 UI 解耦 → 同一功能可同时出现在顶部功能区和右侧紧凑栏；便于逐步交付与取舍。
