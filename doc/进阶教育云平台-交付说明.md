## 一、v1.4 改了什么

**一句话**：只动表结构，不动功能范围。FR 仍 95 条、页面仍 85 个、NFR/SEC 条数都没变，表从 145 张减到 140 张。

### 1.1 删除状态改三态（你提的第 1 条）

`deleted` 由两态改为三态，全库 140 张表统一：

| 值 | 含义 | 业务列表可见 | 可恢复 |
|----|------|--------------|--------|
| `0` | 未删除 | 是 | — |
| `1` | 已入回收站 | 否（仅回收站） | 是 → `0` |
| `2` | 已彻底删除 | 否 | 否（终态） |

**允许的路径只有三条**：`0→1`（删除进回收站）、`1→0`（回收站恢复）、`1→2`（彻底删除）。

**明确禁止四条**：`0→2`（跳过回收站）、`2→1`、`2→0`（终态回跳）。

拦截不靠代码自觉：所有更新与恢复语句固定带 `WHERE deleted=1`，`deleted=2` 在 SQL 层面天然不匹配。

配套改动：`sys_recycle_bin.restored_flag` → `bin_status`（0 已恢复 / 1 在回收站 / 2 已彻底删除），与业务表三态同构，不一致纳入对账告警。

落点：数据库文档新增 **1.3 节**（完整状态表 + 迁移表 + 禁止路径表 + 5 条配套约定）；需求说明书改 9.1 公共字段、新增 9.3 状态机行、重写 **FR-T-CM-04 回收站**（3 条 TC → 5 条，覆盖禁止路径）、NFR-11、SEC-15、3.3 全局机制。

### 1.2 教案/学案/讲义/课件合并为一张表 + 单个大文本内容字段（第 2 条）

原设计里四类文档的内容散在 5 处：`t_teach_doc.content`（正文流）+ `t_teach_plan`（教案 10 个结构化字段）+ `t_teach_plan_step`（教学过程环节）+ `t_teach_doc_block`（讲义/学案块）+ `t_teach_doc_slide`（课件分页）。

**v1.4 合并为**：一张 `t_teach_doc`，一个 `content LONGTEXT`。

删掉 4 张表：

| 删掉的表 | 原职责 | 内容去哪了 |
|----------|--------|-----------|
| `t_teach_plan` | 教案三维目标/重难点/方法/教具/板书/反思 10 个字段 | 变成正文里的**固定二级标题章节** |
| `t_teach_plan_step` | 教学过程环节（教师活动/学生活动/设计意图/时间） | 变成正文里的**一张表格**，行带 `data-step` |
| `t_teach_doc_block` | 讲义/学案段落块 | 变成 `<section data-block="…">` 标签 |
| `t_teach_doc_slide` | 课件分页（版式/要点/讲稿） | 变成 `<section class="slide" data-layout="…">` |

`t_teach_doc` 新增 4 个字段，删掉 2 个：

| 字段 | 用途 |
|------|------|
| `content_mode` | `flow` 文档流（教案/学案/讲义）／`slide` 分页（课件）。只决定编辑器打开方式，不影响存储格式 |
| `periods` | 课时数。**唯一保留的教案结构化要素** —— 排课与工作量统计要按数值过滤 |
| `page_count` | 页数。保存时统计 `class="slide"` 段数回写，列表页免解析正文 |
| `cover_url` | 课件封面 |
| ~~`plan_json`~~ | 教案结构化扩展，已无用 |
| ~~`shared_square`~~ | 知识广场分享标记，v1.3 已移出范围 |

**结构化输入也走大文本**：你说的这条我按字面落实了 —— 「按章节填表」和「自由富文本」两种编辑方式的产物写进**同一个 `content` 字段**，切换不丢内容，不存在两份数据。知识点／环节类型／版式这些结构信息用 `data-*` 属性内嵌在 HTML 里，服务端只存不解析，前端按属性渲染。

连带调整：`r_resource_ref.ref_block_id`（BIGINT）→ `ref_anchor`（VARCHAR(64)），改存正文内 HTML 元素 id（如 `q_10086`）。块表没了，引用定位改走锚点，引用保护与跳转照旧。

需求侧重写 3 条 FR：**FR-T-TC-01 教案（列表 + 全文编辑）**、**FR-T-TC-02 学案与讲义（分段富文本编辑）**、**FR-T-TC-03 课件（列表 + 分页富文本编辑）**，测试场景由 9 条增至 13 条。

### 1.3 标准公式库与机构/个人公式库合并（第 3 条）

| 原 | 现 |
|----|-----|
| `r_formula_standard`（标准库，只读） | 合并为 **`r_formula`** 一张表 |
| `r_formula_org`（我的公式 + 机构共享） | 同上 |

用一个字段区分三级：

| `formula_scope` | 含义 | 归属 |
|-----------------|------|------|
| `standard` | 标准公式 | `tenant_id=0`、`owner_id=0`，平台维护，全局只读 |
| `org` | 机构共享公式 | 机构内全员可见，需审核 |
| `personal` | 个人公式 | 仅归属人可见 |

`formula_status` 承载审批态（`approved`/`pending`/`rejected`/`off`），标准公式固定 `approved`。新增 `source_id` 记来源：标准公式被收藏时复制一条 `personal` 记录并指回原公式，取消收藏按 `source_id` 反查 —— 这样「收藏数」和「我的公式」不再是两套数据。

需求侧的 **3 条 FR 不合并**（FR-T-FX-01 标准公式库 / 02 我的公式 / 03 机构共享公式）—— 它们是三个不同页面与三套权限，只是底层共用一张表。共享流程改为「`personal` 翻 `org` + 状态置 `pending`」，驳回则退回 `personal`，不再有 `shared` 这个独立枚举。

## 三、三处需要你留意的判断

### 1. 「价格字段」我按「作用域字段」理解了

你原话是「只是**价格**字段区分下个人、机构还是标准的」。公式库没有定价语义（没有购买、没有结算），所以按 `formula_scope`（作用域）实现：`standard` / `org` / `personal`。

**如果确实要做付费公式库**（比如机构上架公式按份售卖），那是另一个功能，需要加 `price` + 订单 + 结算，得单独立项。请确认我的理解对不对，已记为 **Q-20**。

### 2. 删 4 张表是有代价的，我把代价写清楚了

合并成单字段后，能力上丢了三样东西：

| 丢失的能力 | 影响 | 现在的替代方案 |
|------------|------|----------------|
| 字段级检索 | 不能 `WHERE objectives LIKE '%…%'` 精确查教学目标 | 走正文全文检索；`periods`/`page_count` 这类要过滤的已独立成列 |
| 块级定位 | 引用台账记不到「第 3 块」，只记锚点 | `ref_anchor` 存 HTML 元素 id，前端可跳转；引用保护判断不受影响 |
| 结构化统计 | 「80% 的教案没写教学反思」这类分析做不了 | 需要时用正文解析任务离线跑，不进主库 |

这是「简单」换「可分析性」的取舍。**如果后面要做教研质量分析（教案完整度、章节覆盖率），建议加一张只读的解析结果表**，从 `content` 定时解析出来，别回退成拆字段。已记为 **T-16**（质量分析缺口）与 **T-18**（内容结构的解析依赖）。

### 3. 唯一索引与删除态的处理需要研发确认

`deleted` 变三态后，唯一索引有个绕不开的问题：如果唯一键不含 `deleted`，删掉的记录会永久占着那个业务键，同名对象建不出来；如果含 `deleted`，同一键在 `deleted=1` 和 `deleted=2` 时各占一条，也不算严格唯一。

本期给的口径是「唯一键保持业务字段组合 + 服务层冲突时自动追加序号后缀」。**这条要研发确认能否接受**，不然后面会出现「删除后无法重建同名试卷」的线上问题。已记为 **T-17**。
